在公司加班的时候，无意间看到了这本书，正如书名所说，全书分为四个章节，正是“从点子到产品”，书中所写的内容偏向基础，可以作为产品经理的入门书籍，对于独立开发者来说这本书更是值得一读

豆瓣书评中很多说这本书内容混乱，其实前两章感觉还是非常清晰的，很容易看出作者是用markdown进行编辑的，格式简单，要点分明，而且文字通俗易懂，无论是否从业人员都可以零障碍阅读，全篇看完大概在两到三小时，不会占用太多时间，第三和第四部分，因为内容分散多为叙事所以这里不做过多解读

这本书缺点也很明显，作者是知乎中产品相关高票答主，虽然对于单个问题能一针见血，但是整理成册却在很多地方内容冗余，作为一个互联网从业者而言干货较少，除开理论之外可以用于实践的部分不多，但是作为想要入坑或者是独立开发者来说不失为一本入门好书



### 第一部分：功能设计

![image-20191007145254866](https://tcyeee.oss-cn-hangzhou.aliyuncs.com/note/2019-10-07-065254.png)

实现了用户痛点，产品便有了价值

**1.产品的合理性**

在一个产品设计之初，就需要最为核心的事情：用户为什么要用这个产品，也就是说，这个产品能解决什么样的用户痛点，怎样的产品才算设计得当，这个时候作者给出了一个产品模型的检验矩阵：

![image-20191007102028386](https://tcyeee.oss-cn-hangzhou.aliyuncs.com/note/2019-10-07-022028.png)
<p style="text-align:center;font-size:12px;color:gray;">
产品模型的检验矩阵
</p>

京东创始人刘强东在2015年12月的一次公开演讲中提到的创业成功四个要素：团队、用户体验、成本和效率，后三个正是互联网产品存活发展的关键所在，其他部分因为写的比较浅显暂且不做解读

**2.产品的盈利性**

产品在设计之初就需要考虑“离钱有多近”，也就是这个软件该如何创造收益，互联网产品盈利的方法零零总总不外乎这九种：

1. 广告：中国的软件用户付费意愿相比较低，广告也是产品变现最容易，也是最常见的手段，而广告所带来的收益和投放精度、目标人群直接相关，如果软件中目标人群是宝妈或者年轻女性，那么他们的价值就高于普通男性，目标人群的精确划分可以直接提高和广告商的谈判筹码，书中关于广告的部分只有寥寥几笔，没有着重去写具体的手法，但是这点确是一个独立开发者必须要会的知识，建议查看其他相关书籍补全
2. 售卖：售卖以App Store为主，现在国内的付费意识正在崛起，但对于大部分产品来说并不是一个好的变现手段
3. 增值服务：以各大视频网站会员为主
4. 佣金、抽成：参考各大电商平台
5. 企业服务：一些付费api、或者咨询服务，参考阿里云
6. 时效性权益：参考bilibili会员抢先看，也是一种盈利手段
7. 差异化服务：参考知乎付费问答
8. 提供便利：参考一些免费软件中的付费部分
9. 粉丝经济：参考各种直播平台

**3.产品的扩展性**

通俗一点来说就是“行业的天花板”，如果做的软件所处领域过于狭小，功能无法扩展，无法寻找到新的赢利点，这样对以后的发展是致命的

**4.产品的核心价值**

这个不仅仅是各种产品书籍中所着重提到的，也是我在工作中切身体会的，核心价值就是一个产品最核心的功能，也是90%用户选择这个软件的原因，以我在的公司做的产品为例，公司是做一款类似钉钉的办公软件，其中最为核心的部分就是打卡，而这个功能必须做的有足够优秀，拥有足够的吸引力，公司在做这个软件的时候也给了我很多反面教材，比如在打卡功能设计了付费点，到现在还没有做到考勤的可视化

2016年初，微信之父张小龙在一次演讲中说：“我所认为一个好的的产品是用完即走的，我们认为任何产品都是一个工具，好的工具就是应该最高效的帮助用户完成任务，然后尽快离开，而不是让用户在微信里面永远有处理不完的事情”，其中一句“好的应用都是用完即走的”也在网上引起了广泛关注，这句话也在小程序的设计思想中体验的淋漓精致，而“解决问题”便是产品的核心价值

**5.用户黏性**

关于用户黏性这一点，很多互联网公司容易走入一个误区，过分的关注用户活跃度，用户使用频率，打开率，单次使用时长而这也直接导致了运营过分的去玩花样，搞活动，用于提升用户的各种数据，殊不知这样本末倒置，临时的提升数据的同时也降低了这个产品活动在用户心中的权重，适得其反

还是关于“用完即走”这句话，用完即走并非不要黏性，而是做一个工具应该做的事情，微信朋友圈各种营销内容，心灵鸡汤固然可以提高用户黏性，但是微信朋友圈团队却不留余力的去保证朋友圈的纯净性，这样才是一个产品该有的样子，一个真正能解决问题的产品才能真正留住用户

**6.mvp（最小可用产品）**

mvp(minimun viable product)是埃里克-莱斯的《精益创业》中所提到的概念，它的目的就是快速验证两件事情，一是满足用户需要，二是创建商业价值，通俗一点来说，就是使用最轻量级功能找到用户痛点

能否解决用户痛点一直是衡量一个产品是否能够成功的关键要素，而使用mvp验证正是最为快速的方法，在多次尝试之后找到一个用户爆发的版本，从而定位用户痛点，确定核心功能

设计mvp时候，作者推荐了一些方法，但是重复部分较多就不一一讲述了，核心与[奥卡姆剃刀原理]([https://baike.baidu.com/item/%E5%A5%A5%E5%8D%A1%E5%A7%86%E5%89%83%E5%88%80%E5%8E%9F%E7%90%86/10900565?fr=aladdin](https://baike.baidu.com/item/奥卡姆剃刀原理/10900565?fr=aladdin))一致，也是我现在的签名：如无必要，勿增实体” （Entities should not be multiplied unnecessarily），务必确保产品中只有一个功能，无论第二个功能多么炫酷，让用户对软件有一个心理定位，例如微信和支付宝，无论现在多加了多少功能，但是在用户心中核心功能依旧是聊天和支付一样



### 第二部分：产品功能细分

![image-20191007144337798](https://tcyeee.oss-cn-hangzhou.aliyuncs.com/note/2019-10-07-064338.png)

如果说一个产品就是一个城邦的话，核心功能就王宫城堡，在保证王宫安全的情况下去扩展乡郊或者去修饰城堡（细分功能）

**1.根据场景深挖需求**

“不同的需求都是基于特定场景才会出现的，做产品的时候就应该考虑服务怎样的场景”

例如各种外卖app的后端界面设计更趋向于老人机，声音更大字体更大，便是考虑到外卖员送餐的场景

**2.从人性本质深挖需求**

这一块可以说的地方很多，特别是营销学中将人性的本质深挖到极致了，透过表象，去找到其中人性的需求，满足为底层需求而服务，通过人性底层需求总能带动爆发增长，虽然有些不齿，但却是最为直接的方法

|          | 案例一                 | 案例二               |
| -------- | ---------------------- | -------------------- |
| 用户反馈 | 我想快点减肥           | 想从超市订货送上门   |
| 表层需求 | 需要一个快速减肥的服务 | 需要一个在线超市平台 |
| 深层需求 | 成为一个体态优美的人   | 想便捷的买到生活用品 |
| 底层需求 | 虚荣心、得到尊重和欣赏 | 懒惰、不想出门       |

<p style="text-align:center;font-size:12px;color:gray;">
书中提到的两个案例
</p>

前些时候遍地开花的P2P是利用了人们的逐利心理，而用合规的方式满足人们的色欲也是各大陌生人交友平台正在做的事情，O2O满足了人们的懒惰心理，各类网游满足了人民币玩家的虚荣心理，在人性底层还有安全感、共情需要、社交需要等等，参考马斯洛需求层次理论

马斯洛需求层次理论是由美国心理学家亚伯拉罕·马斯洛于1943年在《人类激励理论》论文中所提出。书中将人类需求像阶梯一样从低到高按层次分为五种，分别是：生理需求、安全需求、社交需求、尊重需求和自我实现需求，这里不过多描述，有兴趣的小伙伴可以去看一下原文

**3.根据问卷调查深挖需求**

书中对用户研究的建议：

1. 避免问卷设计缺陷，例如情趣行业调查发现统计结果几乎没有女性，因为调查的女性用户都害怕隐私泄露而羞于回答，或者引导性问题：你认为黄色比红色更好看吗？之类
2. 样本的把控，参与调查目标人群把控，如二战非常有名的幸存者偏差，还有统计学中常常用来做案例的各种美国总统大选民意调查，这里不过多阐述

**4.根据数据分析功能是否合理**

通过产品埋点所所获取的一线数据都可以直观的反应出问题，一个好的产品经理要对数据敏感，定义事件漏斗是目前最常用的分析方法，即按照步骤顺序连接一个一个事件，可通过分析事件中每个步骤转化率来衡量自身产品设计和运营活动的效果并针对性地进行优化，以电商平台的下单为例:

**5.产品优化**

![image-20191007161938975](https://tcyeee.oss-cn-hangzhou.aliyuncs.com/note/2019-10-07-081939.png)
<p style="text-align:center;font-size:12px;color:gray;">
用户体验的七块
</p>
说到产品优化，就必须要提用户体验，“信息架构之父-Peter Morville”认为一个用户体验分为七块，而这本书也是大致从这几个方面来讲述一个好的产品应该遵循的几个原则，

这一块已经偏向于比较细致的优化了，任何一个你觉得“不太舒服”的地方，在市场上都会放大无数倍，而发现细致的优化点，则是一个好的产品经理应该要做的事情

作者给出的一些优化建议和我提出的“简单化、低龄化思想一致”，我觉得绝大多数用户不会在一个app上面花费哪怕一秒钟的思考，这时候就需要将一个产品做到极致的简单，足够的低龄，甚至让用户即便是不看页面上文字的情况下也能大概知道每个版块所提供的功能以及使用方法

1. 可见性原则：要保证产品的内容、状态、变化都要完整呈现在用户的眼中，反面教材便是一些app的空白页面，这是一个好的app不允许出现的，参考facebook，或者知乎，在内容加载出来之前，页面上会显示大致的缩略图，让用户能知道这个页面大概是做什么的而不是白花花的一片
2. 一致性原则：很多时候在用户使用这款软件之前就已经被市面上大多数软件培养出了一套功能、交互逻辑，而如果不遵循这套逻辑则会造成用户学习成本的增加，这无疑和“简单化、低龄化”的思想相悖，同时在产品中每个功能分区的交互逻辑同理
3. 防呆原则：关于防呆，个人觉得做的最好的还是苹果，在每个容易误操作的地方给出提示
4. 灵活高效原则：有一些操作需要固定的步骤，而每当有固定步骤，则代表这些步骤可以被简化，例如拍照->进入微信->选择图片->发送图片，这些步骤进入微信直接提示是否需要发送图片
![image-20191007165306234](https://tcyeee.oss-cn-hangzhou.aliyuncs.com/note/2019-10-07-085306.png)
5. 恢复现场原则：在很多场景下，用户因为各种情况不小心点击了退出，重新点击回来的时候不需要重复输入，可以恢复之前输入的内容
6. 功能取名原则：抛弃文艺，取名见名知意，能简则简，反复斟酌，防止歧义
